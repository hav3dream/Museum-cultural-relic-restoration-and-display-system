## 1. 产品范围描述

博物馆文物修复与展示系统是一套面向博物馆场景的 B/S 架构 Web 平台，由三部分组成：

1. **前端 Web 应用**：为用户提供修复操作界面、创作工具界面、画廊展示界面与个人控制台，采用响应式设计，视觉风格为博物馆主题配色（深红/鎏金/米黄）；
2. **后端 API 服务**：提供用户认证、积分订阅、修复任务调度、画廊数据、数字人视频状态查询等 REST API，负责业务逻辑与数据持久化（SQLite）；
3. **AI 算法服务层**：以独立 Python 微服务形式部署各学术修复模型（SGRGAN、DCADif、M3SFormer、Relic2Contour、AdaMPI、M3FPainter 等），Web 后端通过 HTTP 接口以代理模式调用，实现算法与业务解耦。

**产品核心价值**：将学术界文物修复研究成果工程化为可在线使用的服务，并配套数字化展示与传播能力。

## 3. 验收标准

1. 表 2.1 中全部 Must 项功能完整可用，端到端操作流程（上传 → 处理 → 查看结果 → 保存/下载）无阻断性缺陷；
2. Should 项完成核心流程，允许在不影响主流程的前提下存在已记录的轻微缺陷；
3. 非功能项 N01～N05 逐项达标；
4. 全部验收测试用例（见《需求跟踪矩阵》映射的测试用例）通过率 100%（Must）/ ≥95%（Should）；
5. 系统在目标部署环境完成安装并稳定运行 48 小时无严重故障；
6. 全部文档交付并经指导教师评审通过。

## 4. 项目除外责任（Out of Scope）

以下内容**不在**本项目范围内：

1. AI 修复模型本身的训练与调优（使用已发表模型的部署与集成）；
2. 移动端原生 App（仅提供响应式 Web）；
3. 真实支付通道对接（Stripe 支付仅以测试模式占位，不接入真实收单）；
4. 多语言国际化（仅中文界面）；
5. 博物馆既有藏品管理系统（如藏品编目 MMS）的数据对接；
6. 文物实体的物理修复（本项目仅限数字图像层面）；
7. 大规模分布式部署与高并发优化（按课程演示规模设计）。

## 5. 制约因素（Constraints）

1. **进度制约**：必须在 2027-01-15（课程期末）前完成全部交付；
2. **算力制约**：AI 推理依赖租赁 GPU 服务器，预算上限 1.5 万元，影响修复并发与响应速度；
3. **人员制约**：团队 5 人均为在校学生，仅能投入课余时间，有效工时按每人每周 20 小时计；
4. **技术制约**：部分学术模型仅有研究代码，工程化封装需适配其输入输出格式；
5. **合规制约**：算法使用须遵循原论文/开源许可，文档注明出处。

## 6. 假设条件（Assumptions）

1. 假设租赁的 GPU 服务器在项目期内可用率 ≥ 95%；
2. 假设团队成员能按计划投入时间，缺勤率 ≤ 10%；
3. 假设公开论文算法在其示例数据集上的修复效果可复现；
4. 假设课程演示所需的样例文物图像可从公开数字博物馆资源获取并合规使用；
5. 假设课程教师可在每个里程碑节点（提前 2 天预约）参加评审。
